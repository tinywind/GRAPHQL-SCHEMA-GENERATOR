# GRAPHQL-SCHEMA-GENERATOR

GRAPHQL-SCHEMA-GENERATOR is a Gradle plugin that generates GraphQL SDL object types and enums from a database schema. It reads the schema through [jOOQ meta](https://www.jooq.org/), the metadata layer behind jOOQ's own code generator, so the generated type and field names are the names jOOQ gives its generated POJOs and properties. A resolver that returns a jOOQ POJO therefore matches the generated GraphQL type by construction.

The plugin owns only the part of a GraphQL schema that mirrors the database: scalar columns and enum values. Relations, computed fields, inputs and root fields stay hand-written, typically as `extend type` declarations next to the generated file.

## Features

- One SDL file with the enums and object types of the selected tables, in a deterministic order.
- Column rules for the usual divergences between a table and its API type: foreign keys are dropped in favour of relations, primary keys are kept, and individual columns can be hidden, kept, retyped or made nullable.
- Default mappings from PostgreSQL types to GraphQL scalars, replaceable per SQL type or per column.
- Table, column and enum comments become GraphQL descriptions.
- A `verifyGraphqlSchema` task that fails when the committed file no longer matches the database, so the generated file can be committed and guarded in CI.
- Fail-closed configuration: a pattern that matches nothing, a column without a mapping, a type without fields or a name clash stops generation with a message naming the rule to change.

## Compatibility

| Component | Supported |
|---|---|
| JDK | 21 or later (jOOQ 3.21 requires it) |
| Gradle | 8.14 and 9.x; the functional test runs 8.14.3 and 9.4.0 with JDK 21 and 25 |
| Database | PostgreSQL is tested. Other dialects are detected through jOOQ meta but not tested. |
| Build script | Kotlin DSL. The nested blocks are Kotlin lambdas. |

## Installation

The plugin is not published to a repository. Include the build from a clone or a Git submodule in `settings.gradle.kts`:

```kotlin
pluginManagement {
    includeBuild("../GRAPHQL-SCHEMA-GENERATOR")
}
```

Then apply it and add your JDBC driver to the `graphqlSchema` configuration in `build.gradle.kts`:

```kotlin
plugins {
    id("org.tinywind.graphql-schema-generator")
}

repositories {
    mavenCentral()
}

dependencies {
    graphqlSchema("org.postgresql:postgresql:42.7.13")
}
```

## Configuration

```kotlin
graphqlSchema {
    jdbc {
        // Optional: the first driver on the graphqlSchema classpath that accepts the URL is used otherwise.
        driverClass = "org.postgresql.Driver"
    }
    database {
        url = "jdbc:postgresql://localhost:5432/mydb"
        user = "postgres"
        password = "postgres"
        inputSchema = "public"
        includes = ".*"
        excludes = "flyway_schema_history"
    }
    generator {
        outputFile = layout.projectDirectory.file("src/main/resources/graphql/generated.graphqls").asFile
        tables {
            include("board", "committee", "post", "user", "event_rsvp", "feed")
        }
        columns {
            excludeForeignKeys = true
            keepPrimaryKeys = true
            exclude("user.password_hash")
            include("feed.post_id", "feed.event_id")
        }
        types {
            map("jsonb", "String")
            override("audit_log.changes", "String")
            nullable("post.title")
        }
        enums {
            includeUnreferenced = false
            include("draft_type")
        }
        descriptions = true
        header = null
    }
}
```

### Reference

- **jdbc**
    - `driverClass` - JDBC driver class. When unset, the drivers on the `graphqlSchema` configuration are discovered through `ServiceLoader` and the first one that accepts the URL is used.
- **database**
    - `url`, `user`, `password` - Connection settings. The password never appears in messages, and a JDBC URL is printed without its query string.
    - `inputSchema` - Schema to read. Blank reads every schema the connection can see.
    - `includes` - Regular expression of the tables loaded from the database, as in jOOQ. Defaults to `.*`.
    - `excludes` - Regular expression of the tables never loaded, as in jOOQ. Defaults to none.
- **generator**
    - `outputFile` - The SDL file to write. Required.
    - `header` - Text written before the first declaration. Unset writes `# Generated by GRAPHQL-SCHEMA-GENERATOR from database schema "<schema>". Do not edit.`; a blank string writes nothing. Lines that do not start with `#` are turned into comments.
    - `descriptions` - Writes table, column and enum comments as descriptions. Defaults to `true`.
    - **tables** - `include(patterns)` selects the tables that become types; `exclude(patterns)` removes tables the includes selected. At least one include is required: a schema is never exposed by accident, and a new table never appears in the API until it is listed.
    - **columns**
        - `excludeForeignKeys` - Drops columns that take part in a foreign key. Defaults to `true`.
        - `keepPrimaryKeys` - Keeps foreign-key columns that also form the primary key, such as the columns of a composite key. Defaults to `true`.
        - `include(patterns)` - Keeps columns the foreign-key rule would drop.
        - `exclude(patterns)` - Hides columns. An exclusion wins over every other column rule.
    - **types**
        - `map(sqlType, graphqlType)` - Replaces or adds the GraphQL type of an SQL type name as the database reports it, such as `character varying`, `jsonb` or the name of a domain.
        - `override(pattern, graphqlType)` - Replaces the base type of matching columns; the first matching override wins. The value is written as given, so `"[String]"` is valid.
        - `nullable(patterns)`, `nonNull(patterns)` - Override the nullability the column declares. A column matching both fails generation.
    - **enums**
        - `includeUnreferenced` - Emits every enum of the schema. Defaults to `false`, which emits only the enums a generated field refers to.
        - `include(patterns)` - Emits matching enums even when no field refers to them.

Patterns are regular expressions matched against the whole name, case-insensitively. Table and enum patterns match the database name; column patterns match `table.column`. Every pattern must match at least one object among the loaded tables, the selected tables' columns or the schema enums; otherwise generation fails, so a rename in the database cannot leave a stale rule behind.

### Column rules

For each column of a selected table, the rules apply in this order:

1. A matching `columns.exclude` pattern hides the column.
2. A matching `columns.include` pattern keeps it.
3. A column that takes part in a foreign key is dropped when `excludeForeignKeys` is on, unless it also belongs to the primary key and `keepPrimaryKeys` is on.
4. Every other column is kept.

A kept column is written as `<field>: <type>` with `!` when the column is `NOT NULL`, subject to the `nullable` and `nonNull` overrides. The field name is the column name in camel case, the type name is the table name in Pascal case, and enum names follow the same rule, exactly as jOOQ names its generated classes and properties. A table that keeps no column fails generation, because GraphQL does not allow an empty type.

### Default type mapping

| SQL type (as reported by the database) | GraphQL type |
|---|---|
| `uuid` | `UUID` |
| `character varying`, `varchar`, `character`, `bpchar`, `char`, `text`, `name`, `citext`, `inet`, `cidr`, `macaddr`, `macaddr8` | `String` |
| `integer`, `int4`, `smallint`, `int2` | `Int` |
| `bigint`, `int8` | `Long` |
| `boolean`, `bool` | `Boolean` |
| `real`, `float4`, `double precision`, `float8` | `Float` |
| `numeric`, `decimal` with a scale of 0 and a precision of at most 9, 18, or more | `Int`, `Long`, `BigInteger`, as jOOQ generates for zero-scale decimals |
| other `numeric`, `decimal` | `BigDecimal` |
| `timestamp with time zone`, `timestamptz` | `DateTime` |
| `timestamp without time zone`, `timestamp` | `LocalDateTime` |
| `date` | `Date` |
| `time with time zone`, `timetz` | `Time` |
| `time without time zone`, `time` | `LocalTime` |
| `json`, `jsonb` | `JSON` |
| enum type | the enum, in Pascal case |
| array | `[<element type>!]`, nested once per dimension |

`UUID`, `Long`, `BigInteger`, `BigDecimal`, `DateTime`, `LocalDateTime`, `Date`, `Time`, `LocalTime` and `JSON` are the scalar names of [graphql-java-extended-scalars](https://github.com/graphql-java/graphql-java-extended-scalars); declare the ones you use in a hand-written file. Binary, interval and unknown user-defined types have no default: map them with `types.map`, retype the column with `types.override`, or hide it with `columns.exclude`.

### Output

Enums come first, then object types, each group sorted by name; fields keep the column order. Descriptions come from comments and use block strings when they span lines or contain quotes.

```graphql
# Generated by GRAPHQL-SCHEMA-GENERATOR from database schema "public". Do not edit.

"Board categories."
enum BoardType {
    NOTICE
    GENERAL
    COMMITTEE
}

type Board {
    id: UUID!
    name: String!
    """
    NOTICE allows guest reading; "quoted" words stay.
    """
    boardType: BoardType!
    cohortNumber: Int
    active: Boolean!
    displayOrder: Int!
    createdAt: DateTime!
}
```

Relations and computed fields belong in a hand-written file next to it:

```graphql
extend type Board {
    committee: Committee
    postCount: Int!
    latestPosts: [Post!]!
}
```

## Tasks

```sh
./gradlew generateGraphqlSchema
./gradlew verifyGraphqlSchema
```

`generateGraphqlSchema` writes the file. `verifyGraphqlSchema` regenerates the SDL in memory and fails with the first differing line when the file is missing or different, so a build that runs it refuses a schema change that was not regenerated and committed. Both tasks read the live database, run every time and are not compatible with the configuration cache.

## Development

```sh
./gradlew build
```

The unit tests need nothing. The PostgreSQL tests start a `postgres:18-alpine` container through Testcontainers and are skipped when Docker is not reachable. The functional test runs consumer builds with Gradle 8.14.3 and 9.4.0 on the JDK 21 and 25 installations found under `~/.sdkman/candidates/java` and is skipped when none is installed. `jacocoTestCoverageVerification` requires 80% instruction coverage.
